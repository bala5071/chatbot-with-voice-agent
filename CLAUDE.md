# CLAUDE.md

## Project story

A self-hosted voice receptionist for a **mock** clinic. A caller speaks; the agent transcribes
the speech, asks a language model for a reply through the
[Multi-Model Inference Gateway](https://github.com/bala5071/Multi-Model-Inference-Gateway-Simulator)
over HTTP, and speaks the reply back. Everything runs on one machine: speech-to-text
(faster-whisper), the gateway in front of Ollama, and text-to-speech (Piper).

This is a demo for synthetic data. It is not a medical device, gives no medical advice, and is
not HIPAA compliant. The clinic, its staff, its hours and every caller are made up.

Stack: Python 3.11+, asyncio, httpx, pytest, ruff, mypy, uv. Free/open-source tools only. Every
runtime dependency, model weight and voice is recorded with its license in `docs/licenses.md`.
The repository is GPL-3.0-or-later because Piper (GPL) runs in the same process.

The plan is `docs/voice-plan.md`. Each step adds a short design note in `docs/NN-<topic>.md`.

## Architecture

Modules under `src/voice_agent/` (added step by step):

- `clock.py` — `Clock` protocol, `FakeClock` (tests: time moves only through `advance`),
  `WallClock` (the CLI); times are milliseconds. The only module allowed to read real time.
- `secret.py` — `Secret`: the API key, redacted in `repr`, `str` and format; `reveal()` only
  in `gateway_client._auth_headers` (an AST test).
- `config.py` — `Settings` from the environment (`GATEWAY_URL`, `GATEWAY_API_KEY`,
  `VOICE_MODEL`, timeouts); plain http only to loopback; never a secret in a file.
- `audio.py` — `Audio` (16-bit mono PCM in memory), WAV in and out.
- `interfaces.py` — `SpeechToText`, `TextToSpeech`, `ChatClient`, `Message`.
- `fakes.py` — the deterministic fake of each interface, on `FakeClock`.
- `engines/` — the real engines: `faster_whisper.py`, `piper.py` (the only module importing
  Piper). Imported only by the CLI and scripts, never by logic modules.
- `errors.py` — `SpokenError` and its subclasses, each with fixed spoken text; the status and
  stream-code mapping.
- `gateway_client.py` — `GatewayClient`: the streamed `POST /v1/chat/completions`, timeouts on
  the injected clock.
- `sentences.py` — splits a streamed reply into sentences for TTS.
- `safety.py` — the scripted emergency detector and its fixed response.
- `clinic.py` + `clinic.toml` — the mock clinic's facts and the system prompt.
- `timing.py` — `Stage`, `StageTimer`: the six stage timestamps on the injected clock.
- `pipeline.py` — `Pipeline`: warm-up and one push-to-talk turn.
- `cli.py` — `python -m voice_agent`: audio file in, audio file out.

Outside the package: `models.toml` (pinned model files and hashes), `scripts/fetch_models.py`,
`scripts/gpu_budget.py`, `scripts/measure_latency.py`, `scripts/check_characters.py`.

Rules:

- `cli.py` is the only wiring point. It builds components and injects their dependencies.
- Logic modules never construct their own clock, RNG, engine or HTTP client.
- Dependencies point inward: cli → pipeline → stt/tts/chat interfaces → clock.

Tests that need real models or a running gateway are marked `real_models` and skipped unless
`VOICE_REAL_MODELS=1`. CI never runs them and never downloads a model.

## Hard rules

1. **Injectable Clock.** Every component that times or waits takes a `Clock`: `FakeClock` in
   tests and CI, `WallClock` in the CLI. No `time.sleep`, `asyncio.sleep` or direct
   `time.time()`/`perf_counter()` in logic. Ruff enforces this (`TID251` banned-api in
   `pyproject.toml`); only `src/voice_agent/clock.py` is exempt. Do not add `noqa` to get
   around it.
2. **Interfaces with fakes.** STT, TTS and the chat client each sit behind an interface with a
   deterministic fake, so CI needs no models and no network. A fake takes its timings from the
   test and advances the injected clock; it never reads real time or a global `random`.
3. **Every step ships with tests and a design note.**
4. **Never claim a number that was not measured.** Any figure in the README, docs, commits or
   PRs names the command and commit that produced it, and the hardware it ran on. If it wasn't
   run, don't write a number. A table waiting for a measurement stays empty.
5. **Mock clinic data only.** No real patient, staff or clinic data anywhere, including tests,
   fixtures, prompts and examples. Names, phone numbers and addresses are visibly fake.
6. **Synthetic test audio only.** Test audio is generated by this repo's TTS (or by the fakes),
   never a recording of a real person.
7. **Secrets only from environment variables.** Never in code, YAML, logs, errors, reprs,
   prompts, tests, test output, fixtures, PR text or commits.
8. **Nothing stored by default.** No audio or transcript is written anywhere unless the user
   asks for it (the CLI's output file is asked for; nothing else is). Logs carry stage names and
   timings, never transcript or reply text.
9. **No medical advice; emergencies are scripted.** The emergency response is fixed text,
   chosen by `safety.py` before any model call, never generated. The model is told to stay a
   receptionist; that instruction is not a guarantee, and the docs say so.
10. **Ask before any download.** Before downloading any model or voice, state its name, size,
    license and source, and wait for an explicit yes.

## Coding conventions

- Full type hints; mypy runs in strict mode over `src`, `tests` and `scripts`.
- `from __future__ import annotations` at the top of every module.
- Frozen dataclasses for value types.
- Async-first: logic that waits does so through the `Clock`.
- No module-level mutable state.
- Randomness comes from a seeded `random.Random` instance that is passed in.
- Line length 100; `ruff format` is the formatter.

## Working agreement

These apply to every task without being repeated.

**Process**

- Each step gets its own branch and PR. The first commit is the plan update. Open the PR as a
  draft with `gh`, put the reviewer-facing description in the PR body, wait for CI with `gh`,
  fix failures that are not in the stop list, then report.
- Plan approval is required only for tasks that touch secrets, audio capture or storage, a
  network client or surface, or a model download. For all other tasks, write the plan as the
  first commit and continue.
- The next step may start from the previous branch once its CI is green. Say clearly which PRs
  must be merged in which order.
- When a PR is stacked on another branch, state its base at the top of the description and in
  the report. Before the user merges, run `gh pr view <n> --json baseRefName` and say whether the
  base is `main`; a PR is never described as ready to merge unless its base is `main`. When a
  base PR merges, retarget the next PR at once (`gh pr edit <n> --base main`), check its CI
  again, and report.

**Definition of done** (real output shown, never summarized): ruff, the format check, mypy, the
full pytest, `scripts/check_characters.py`, and every CI job green.

**Security rules**

- Every rule about who may do what, or what is refused, has a mutation check: break it, show
  which tests fail, restore it byte for byte, show the tests pass again.
- Any new path that handles a secret gets the leak scan with a planted control that must be
  found.
- Any refusal path in authentication gets a structural test that every case takes the same
  steps, plus the early-return mutation.
- A missing resource and a forbidden one get the same response, byte for byte.
- No secret in logs, errors, audit entries, test output, PR text or commits.

**Measurement rules**: performance statements are measured on this machine, with the hardware
recorded and a range over three runs. Never state an unmeasured number. Label simulated results
as simulated, and results from one machine as one machine.

**PR description template**, sections in order: What changed; Decisions not in the request
(numbered, so they can be objected to); Mutation checks (a table); Timing (with hardware);
Threat-model additions; Not built; Checks; CI result.

**Stop and ask when**

- a check fails and the fix would change a tolerance or a recorded result;
- a security or safety semantic is ambiguous;
- a secret, key, account or model download is needed;
- a test cannot be made to fail under mutation;
- an unexpected file is tracked, or a dependency is added (pin it, check its license, and record
  it in `docs/licenses.md` first);
- anything would require a destructive git command.

**Never** merge a PR, push to main, refresh a baseline to make a check pass, print a secret, stop
a process you did not start, or run `git reset --hard` or any command that discards work.

## Commands

```sh
uv sync                      # create .venv and install everything
uv run ruff check .          # lint
uv run ruff format --check . # formatting (drop --check to apply)
uv run mypy                  # type check
uv run pytest                # tests (fakes only)
uv run python scripts/check_characters.py   # tracked code is printable ASCII
uv run python scripts/gpu_budget.py         # Whisper + the voice tier fit on this GPU
uv run python -m voice_agent --in in.wav --out out.wav   # one push-to-talk turn
```

All of these except the last two must pass before a step is called done. CI runs them on
Python 3.11 and 3.12.
